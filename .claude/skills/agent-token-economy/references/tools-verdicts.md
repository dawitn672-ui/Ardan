# Outside tools, skills and plugins: what each really does and the verdict (read 2026-11-27)

Rule (order 101): read the source, adapt the idea into our own skill or script, never install unread. Nothing below
was installed. Vendor token claims come from the vendors' own benchmarks; none is independent. Sources are the raw
README/SKILL files named in each row.

## The three tools the owner asked about

Repo facts for judging them: Ardan is about 31 MB of `src` (740 JS files), the release's core files run to 100 KB each,
there is a working symbol finder (`tools/show.mjs --where A.name`), containers are wiped between sessions, up to five
builders work in separate worktrees (separate directories, so no shared index), Notion holds information.

| Tool | What runs, stores, sends | Claimed saving | Holds here? | Verdict |
| --- | --- | --- | --- | --- |
| **claude-mem** (thedotmack/claude-mem, README read; license stated as Apache 2.0 with commercial hosted parts) | Hooks on Setup, SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Stop, SubagentStop, SessionEnd, each running `claude-mem hook claude-code <event>`; a local Bun worker with an HTTP viewer; SQLite at `~/.claude-mem/claude-mem.db` plus Chroma. **A separate "observer" model call turns every tool use into observations and summaries**, through the hosted claude-mem observer (30-day trial), your own OpenRouter/Gemini key, or your Anthropic plan: it spends tokens of its own on every tool call and sends session content to that provider. Telemetry on by default; cloud sync opt-in. Needs Node 20.19+, Bun, uv. | Progressive disclosure (search about 50 to 100 tokens a result, then details 500 to 1,000); its own README says the ratio "is not a measured recall or end-to-end saving"; "up to 100% more plan usage" has no method. | No. Memory in `~/.claude-mem` is lost when the container is wiped; the observer re-spends tokens each session on a repo whose record is already in HISTORY/DECISIONS/LESSONS and Notion; hooks on every tool call in five parallel agents multiply the cost; content leaves to a provider. | **Skip.** Idea to keep: progressive disclosure, which our Notion index-then-child pages and `docs/README.md` index already are. |
| **graphify** (safishamsi/graphify, mirror Graphify-Labs/graphify; README read; PyPI name `graphifyy`; license not stated in the README) | `/graphify .` builds `graphify-out/` (graph.json, GRAPH_REPORT.md, html, cache). Code: tree-sitter AST locally, no model. **Documents, papers and images go through Claude for concept extraction (spends tokens, sends content out).** Optional `graphify claude install` writes a CLAUDE.md section and a **PreToolUse hook on every Glob and Grep**; optional post-commit hook rebuilds. Python 3.10+. | 71.5x fewer tokens per query on one 52-file corpus of code, papers and diagrams; 5.4x on 4 files; about 1x on 6 files; says gains grow with corpus size. | Partly: our `docs/` (15 MB) is the mixed corpus it would send through a model (cost, and docs are being moved to Notion anyway); the code part duplicates `tools/show.mjs`. Graph rebuilt every session in a wiped container; a hook on every Glob/Grep in every agent adds turns. | **Skip as installed; adapt the idea** (below). |
| **A code graph** ("code graph" is several tools; the two most discussed for Claude Code: **colbymchenry/codegraph** and **DeusData/codebase-memory-mcp**; READMEs read) | codegraph: MCP server plus file watcher per session, `.codegraph/codegraph.db` (SQLite, FTS5), tree-sitter, JS full support, edits CLAUDE.md and adds auto-allow permissions unless `--no-permissions`; no model or embedding API; **telemetry on by default** (off with `DO_NOT_TRACK=1`); MIT. codebase-memory-mcp: one native binary, 17 MCP tools, graph in `~/.cache/codebase-memory-mcp/`, on-device embeddings, says no telemetry, `install` writes client config, skills and hooks (off with `--no-hooks`), optional committed snapshot `.codebase-memory/graph.db.zst`; MIT. | codegraph: 88% fewer tool calls, 62% fewer tokens, 44% cheaper (vendor harness, Opus, 4 runs a repo, one question each; it also notes about 80% more context left resident). codebase-memory-mcp: about 10x fewer tokens, 2.1x fewer tool calls in a 31-repo preprint (arXiv 2603.27277), tells you to measure your own workload. | Useful in principle for "who calls A.fightWorth": but the release is one global namespace `A.*` with event functions kept as minified text lines that the engine reads as text, so call-graph precision is low; indexing 31 MB per session per worktree costs minutes of CPU on a shared box; the grep + `show.mjs` route already answers most questions in a few hundred tokens. | **Skip install. Adapt:** a `tools/symbol-index.mjs` that writes a plain text index (symbol, file, line, one line of purpose) into the build's output, grep-able, no daemon. If a trial is wanted later: codebase-memory-mcp with `--no-hooks`, on one scratch worktree, measuring tokens with and without on three fixed questions. |

Honest estimate of the realistic saving for Ardan from all three: small and uncertain. The big costs here are bulk
data through a model, too many agents, long test output and a large CLAUDE.md: those levers (SKILL.md 1 to 6) save more
than any graph. A code-structure aid pays when agents open many files to find one function; the fix that costs nothing
is to put `file:line` in the brief.
